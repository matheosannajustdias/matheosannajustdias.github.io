PROC-02Réseau · 7 pages

DHCP redondant avec failover

Deux serveurs DHCP qui se partagent l'adressage des VLAN. Si l'un tombe, l'autre prend le relais et garde les mêmes baux.

Principal
172.16.2.245
Secondaire
172.16.2.246
Domaine
M2L.local
  1. Adresse IP fixe des deux serveurs
  2. Une plage d'adresses par VLAN dans dhcpd.conf
  3. Failover : un serveur primary, un secondary, charge partagée
  4. Redémarrage de isc-dhcp-server et vérification
Voir la configuration 
failover peer "M2L-DHCP" {
  primary;
  address 172.16.2.245;  port 647;
  peer address 172.16.2.246;  peer port 647;
  max-response-delay 60;
  mclt 3600;  split 128;
}

subnet 172.16.10.0 netmask 255.255.255.0 {
  option routers 172.16.10.254;
  option domain-name-servers 172.16.2.242, 172.16.2.243;
  pool {
    failover peer "M2L-DHCP";
    range 172.16.10.1 172.16.10.60;
  }
}

PROC-03Haute dispo · 6 pages

HAProxy : répartition de charge

Répartit les visiteurs du site entre deux serveurs web. Un serveur qui ne répond plus est mis de côté automatiquement.

HAProxy
192.168.0.2
WEB1 / WEB2
192.168.1.2 / .3
Stats
port 8404
  1. Installation et démarrage de HAProxy
  2. Frontend qui écoute sur le port 80
  3. Backend en roundrobin avec test de santé
  4. Page de statistiques, vérification et test
Voir la configuration 
backend wordpress_web
  balance roundrobin
  option httpchk GET /
  server WEB1 192.168.1.2:80 check
  server WEB2 192.168.1.3:80 check

listen stats
  bind 192.168.0.2:8404
  stats enable
  stats uri /stats

haproxy -c -f /etc/haproxy/haproxy.cfg
systemctl restart haproxy

GLPI relié à l'Active Directory

Gestion du parc et des tickets, connectée à l'annuaire, avec la base déplacée sur un serveur de bases de données dédié.

GLPI
172.16.2.247
Annuaire
M2L-AD1 · 172.16.2.242
Base
M2L-SGBD · 192.168.1.4
  1. Apache, MariaDB, PHP, installation de GLPI
  2. Liaison LDAP à l'AD (DC=M2L,DC=local)
  3. Export de la base, envoi et import sur M2L-SGBD
  4. Utilisateur limité à l'IP de GLPI, tests du port et du site
Problèmes résolus

Archive de GLPI inutilisable : récupération par git clone. Erreurs MariaDB 1819 et 1410 corrigées (mot de passe trop faible, GRANT sur un compte inexistant).

Voir la configuration

  > /root/export-bdd/glpi.sql
scp /root/export-bdd/glpi.sql transfert@192.168.1.4:/home/transfert/

# Sur M2L-SGBD
mariadb db_glpi < /home/transfert/glpi.sql

# Vérifications depuis GLPI
nc -zv 192.168.1.4 3306
curl -sS -o /dev/null -w 'HTTP=%{http_code}
' http://127.0.0.1/glpi/
